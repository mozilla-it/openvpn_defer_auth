# openvpn_defer_auth
---
Це простий плагін для OpenVPN для виконання запитів відкладеної автентифікації (deferred authentication).

Навіщо це потрібно?
---
При використанні MFA (багатофакторної автентифікації) зазвичай потрібна взаємодія з людиною. Це спричиняє затримку в процесі автентифікації, а OpenVPN блокує роботу, чекаючи на відповідь. Коли одна людина повільно вводить код, це може впливати на роботу всього сервера. Цей плагін дозволяє винести процес перевірки у фоновий режим.

Конфігурація
---
Після встановлення файлу ```openvpn_defer_auth.so``` додайте наступний рядок до вашої конфігурації OpenVPN:

```
plugin /usr/lib64/openvpn/plugins/openvpn_defer_auth.so /usr/lib/openvpn/plugins/duo_openvpn.py
```

Це вказує OpenVPN використовувати цей плагін... а плагін своєю чергою виконeє (через fork+exec) вказаний файл скрипт (у прикладі вище — Python duo_openvpn) для проведення автентифікації та повернення результату (успіх/помилка).

Збірка
---
Існує підкаталог ```build_notes```, у якому пояснюється методологія збірки цього плагіна. Зокрема, як ми перейшли від «прикладу коду, що поставляється з OpenVPN» до «нашого плагіна».

Ліцензія
---
Вихідний код цієї бібліотеки поширюється за ліцензією GPLv2, так само як і OpenVPN 2.
Плагін значною мірою базується на їхньому прикладному коді.

Сумісність
---
Початково плагін був протестований на версії 2.4.6 і успішно працював на всіх версіях до 2.6.14 включно.




Інструкція із збірки та встановлення openvpn_defer_auth
---
Цей плагін дозволяє OpenVPN обробляти запити на автентифікацію в неблокуючому режимі (deferred authentication).

1. Попередні вимоги:
---
Для успішної збірки вам знадобляться:

```
    GCC (GNU Compiler Collection)
    Make
    Git (для визначення версії з коміту)
    Заголовочні файли OpenVPN (зазвичай пакет openvpn-devel або openvpn-dev)
```

2. Компіляція
---
Для створення спільного об'єкта (openvpn_defer_auth.so) виконайте:

```
    make
```

3. Встановлення
---
Щоб встановити плагін у системні директорії (за замовчуванням у /usr/lib64/openvpn/plugins або /usr/lib/... залежно від архітектури):

```
    sudo make install
```

4. Встановлення з очищенням символів (Strip)
---
Якщо ви хочете зменшити розмір бінарного файлу, видаливши налагоджувальну інформацію:

```
    sudo make install-strip
```

5. Опції конфігурації
---
Ви можете змінювати поведінку встановлення, передаючи змінні безпосередньо в команду make.

```
    Var     -   DefValue    -   Description
    PREFIX  -   /usr        -   Базовий шлях для встановлення.
    DESTDIR -   (пусто)     -   Шлях для тимчасового встановлення (корисно для створення пакетів).
    CC      -   gcc         -   Компілятор C.
    CFLAGS  -   fPIC        -   Прапорці компілятора.
```

6. Приклад використання:

```
# Встановлення в /usr/local замість /usr
    sudo make PREFIX=/usr/local install
```

```
# Встановлення в кастомну директорію для тестування
    make DESTDIR=/tmp/build install
```

7. Додаткові команди
Створення RPM-пакету
Для створення RPM-пакету використовується утиліта fpm. Переконайтеся, що вона встановлена у вашій системі.

```
    make rpm
```

Пакет буде створено на основі версії 1.4.0 та поточного Git-хешу.


8. Видалення
Щоб видалити встановлений плагін із системи:

```
    sudo make uninstall
```

9. Очищення
Видалення об'єктних файлів, скомпільованого плагіна та тимчасових файлів збірки RPM:

```
    make clean
```

10. Технічні деталі (Автоматизація шляхів)

Makefile автоматично визначає архітектуру системи для вибору правильної директорії бібліотек (LIBDIR):

```
    Linux x86_64: /usr/lib64/openvpn/plugins
    Linux i686 / Darwin: /usr/lib/openvpn/plugins
```
